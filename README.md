# Практическая работа № 1. Вариант 11

Консольный эмулятор UNIX-подобной оболочки. VFS загружается из JSON.
Все изменения файловой системы выполняются в оперативной памяти.
Исходный JSON не перезаписывается. Двоичные данные представлены в base64.

## Требования и запуск

Python 3.10 или новее; внешние библиотеки и сборка не требуются.
Клонируйте репозиторий или скачайте ZIP, откройте терминал в папке проекта.

Linux/macOS:

```sh
./run.sh
./run.sh --vfs examples/vfs/deep.json --script examples/scripts/stage5.txt
```

Windows:

```bat
run.bat
run.bat --vfs examples/vfs/deep.json --script examples/scripts/stage5.txt
```

Альтернатива для всех ОС:

```sh
python -m src.main
python -m src.main --vfs examples/vfs/files.json
python -m src.main --script examples/scripts/stage4.txt
```

На Linux/macOS можно заменить `python` на `python3`.
Если исполняемый бит run.sh утрачен при распаковке, используйте `sh run.sh`.
Пути запуска относительно текущей папки; run.sh/run.bat переходят в папку проекта.

## Параметры

- `--vfs ПУТЬ`: JSON-файл VFS. По умолчанию `examples/vfs/deep.json`.
- `--script ПУТЬ`: необязательный стартовый скрипт UTF-8.
- `-h`, `--help`: справка argparse.

При запуске оба заданных параметра выводятся с префиксом `[config]`.
Приглашение: `имя_VFS:/текущий/путь$`.
Стартовый скрипт отображает команды и результаты как диалог с пользователем.
Пустые строки и строки, начинающиеся с `#`, пропускаются.
Первая ошибка прерывает весь запуск, печатается путь скрипта и номер строки.
Если скрипт завершается без `exit`, начинается интерактивный REPL.
В REPL ошибка не прерывает оболочку; EOF/Ctrl+C завершает ввод.

Коды возврата: 0 - нормальное завершение, 1 - ошибка VFS/стартового скрипта,
2 - неверные параметры командной строки.

## Команды

| Команда | Поведение |
| --- | --- |
| `ls [-a] [-l] [путь ...]` | Список каталога или информация о файле. |
| `ls -al` | Объединение флагов; скрытые имена, тип, права и размер. |
| `ls -- путь` | Завершение обработки флагов. |
| `cd [путь]` | Переход в каталог; без аргумента - в корень VFS. |
| `find [путь]` | Рекурсивный обход, по умолчанию текущий каталог. |
| `find [путь] -name шаблон` | Фильтр имени: `*`, `?`, `[abc]`. |
| `find [путь] -type f\|d` | Фильтр файлов или каталогов. |
| `clear` | Очистка экрана ANSI-последовательностью. |
| `chmod [-R] режим путь ...` | Права из трех восьмеричных цифр; `-R` - рекурсивно. |
| `mkdir [-p] путь ...` | Создание каталогов; `-p` создает недостающих родителей. |
| `vfs-load путь` | Загрузка нового JSON с диска и переход в его корень. |
| `exit` | Завершение оболочки без аргументов. |

Фильтры `find -name` и `-type` можно сочетать в любом порядке.
При нескольких путях `ls` печатает заголовки. Размер в `ls -l` - байты файла;
у каталога размер 0. Список отсортирован по именам.
`ls -a` также показывает `.` и `..`.
`mkdir` создает каталоги с правами 755, `mkdir -p` допускает существующие каталоги.
В JSON допустимы скрытые имена и имена без пробельных символов.
Парсер команд намеренно простой: `str.split()` по пробелам, без кавычек,
переменных окружения, перенаправлений и конвейеров. Шаблоны вводятся без кавычек.
Имена, начинающиеся с дефиса, можно задавать как `./-имя`.
При запуске через реальную оболочку шаблон `find` вводится внутри эмулятора.

### Права доступа

Эмулятор работает как владелец каждого узла. Все девять битов прав хранятся,
а проверки используют биты владельца: `r` - чтение каталога, `w` - создание
в каталоге, `x` - переход/обход. `ls` и обход `find` требуют `r+x`;
`mkdir` требует `w+x` у родителя; `cd` требует `x`.
`chmod` может вернуть права закрытому узлу, если доступен его родитель.
Рекурсивный `chmod -R` сначала обходит поддерево: для обхода каталогов нужны `r+x`.
Режимы chmod числовые: например 600, 700, 755; символические режимы не реализованы.
Это VFS с одним владельцем, без системных пользователей, ACL и умаски.

## Формат VFS

```json
{
  "name": "demo",
  "entries": [
    {"path": "/docs", "type": "dir", "mode": "755"},
    {"path": "/docs/hello.txt", "type": "file", "mode": "644",
     "encoding": "base64", "data": "SGVsbG8K"}
  ]
}
```

Корень `/` существует неявно с правами 755; его можно описать явно как каталог.
`mode` можно опустить: каталог получает 755, файл - 644.
`name` - непустое имя; `entries` - список узлов, порядок узлов произвольный.
Все пути абсолютные, уникальные и канонические: без `.`/`..`, пустых компонентов
и конечного `/` (кроме самого корня). Родители должны быть перечислены как каталоги.
Для каждого файла обязательны `encoding: base64` и `data` с корректной base64-строкой.
Каталоги не содержат `data`. Неизвестные типы узлов, плохие права и отсутствующие
родители вызывают ошибку. Исходный файл читается целиком и затем больше не используется
до следующей команды `vfs-load`. При ошибке `vfs-load` прежняя VFS и cwd сохраняются.

Примеры образов:

- `minimal.json`: пустой корень.
- `files.json`: несколько файлов, включая двоичные байты 00 01 02 FF.
- `deep.json`: три вложенных каталога `/home/student/docs`, файлы и скрытый каталог.
- `invalid.json`: намеренно неправильный формат для проверки обработки ошибки.

## Пример сеанса

```text
ls -al /
cd /home/student
find . -name *.txt -type f
mkdir -p /new/a/b/c
chmod -R 700 /new
ls -l /new
vfs-load examples/vfs/files.json
find / -type f
exit
```

Демонстрации всех этапов: `examples/scripts/stage2.txt` ... `stage5.txt`.
Ошибка обрывает стартовый скрипт, поэтому ошибочные режимы вынесены в отдельные
сценарии `examples/scripts/errors/`. Эти ошибки ожидаемы при запуске проверок.

## Тестирование

```sh
python -m unittest discover -s tests -v
sh scripts/test_all.sh
```

Windows: `scripts\test_all.bat`. Отдельные сценарии: `test_config`, `test_vfs`,
`test_commands`, `test_extra` в папке scripts, в форматах `.sh` и `.bat`.
Автоматические тесты проверяют вывод команд, пути, режимы, права, двоичные данные,
ошибки, коды возврата, остановку скриптов и отсутствие изменений исходных JSON.
Тесты CLI используют реальный дочерний процесс Python.

## Описание функций

Имена ниже соответствуют исходным файлам; методы класса указаны с именем класса.

### commands.py

- `parse_ls`: Выделить флаги -a, -l и список путей.
- `mode_string`: Показать тип и девять букв прав доступа.
- `show_entry`: Напечатать имя или информацию о типе, правах и размере.
- `ls`: Вывести файлы; -a включает скрытые, -l показывает права.
- `cd`: Перейти в каталог; без аргумента перейти в корень.
- `parse_find`: Прочитать стартовый путь и фильтры -name, -type.
- `find`: Найти узлы рекурсивно по имени и типу.
- `clear`: Очистить ANSI-терминал и поставить курсор в начало.
- `mkdir`: Создать один или несколько каталогов, включая режим -p.
- `chmod`: Изменить числовые права владельца, группы и остальных; -R.
- `vfs_load`: Загрузить новый физический JSON, затем сбросить cwd в корень.

### main.py

- `parse_args`: Прочитать пути к VFS и стартовому скрипту.
- `run_script`: Показать диалог; остановиться при первой ошибке.
- `main`: Напечатать настройки, выполнить скрипт и запустить REPL.

### shell.py

- `Shell.__init__`: Создать пустую VFS и таблицу доступных команд.
- `Shell.prompt`: Вернуть имя VFS и текущий путь в приглашении.
- `Shell.execute`: Разделить ввод по пробелам и выполнить команду.
- `Shell.repl`: Читать команды до exit или конца ввода.

### vfs.py

- `VFS.__init__`: Создать дерево с корневым каталогом.
- `VFS.load`: Прочитать JSON и проверить формат до установки новой VFS.
- `VFS.validate_header`: Проверить имя VFS и список узлов.
- `VFS.validate_path`: В JSON допустимы только канонические абсолютные пути.
- `VFS.parse_mode`: Преобразовать три восьмеричные цифры в битовую маску.
- `VFS.decode_entry`: Проверить узел JSON и декодировать данные из base64.
- `VFS.validate_tree`: Проверить корень и существование родителей-каталогов.
- `VFS.normalize`: Разрешить относительные пути, точку и переходы к родителю.
- `VFS.get`: Найти узел или сообщить об отсутствующем пути.
- `VFS.require`: Проверить биты владельца: эмулятор работает как владелец.
- `VFS.directory`: Проверить, что узел является каталогом.
- `VFS.resolve`: Обойти каждый компонент, проверяя существование и право x.
- `VFS.children`: Вернуть отсортированные непосредственные дочерние пути.
- `VFS.walk`: Обойти дерево итеративно без зависимости от глубины рекурсии.
- `VFS.mkdir`: Создать каталог; -p создает недостающих родителей в памяти.
- `VFS.mkdir_component`: Проверить существующий компонент или создать каталог.
